1. Executive Overview & Problem Statement

Problem Domain Friction

Standardized English proficiency (Aptis / CEFR B1 & B2) serves as an institutional graduation benchmark. However, empirical data shows that over 65% of students fail initial standardized attempts when relying exclusively on unguided self-study lacking personalized diagnostic planning and timely qualitative feedback.

Engineered Solution

AptisGo is a responsive full-stack EdTech platform delivering automated diagnostic placement, daily study roadmaps, instant objective question grading (Reading, Listening, Grammar in <500ms), and an asynchronous lecturer grading queue for subjective audio and essay submissions.

4. System Architecture & C4 Models

C4 Level 1: System Context Diagram
External Actor & HTTPS Boundary Isolation

The System Context isolates student candidates, evaluators, and system administrators. All external traffic communicates via secure TLS/HTTPS channels, directing requests through role-based access validation.

C4 Level 2: Container Diagram
Decoupled Single Page Application & Micro-Services

Architected as a high-performance decoupled system: React Single Page Application (SPA) frontend with declarative state machines, Node.js / Express.js REST API application server, MongoDB BSON Document Database, and an asynchronous object media storage engine.

Problem Domain: Soft Systems Methodology (Rich Picture)

5. Data Architecture & MongoDB Document Model

Entity Relationship & BSON Document Architecture
Data Locality & Nested Question Sub-Documents

Why NoSQL (MongoDB) over SQL: Multi-skill standardized tests possess dynamic, deeply nested question hierarchies (audio stimuli, options, essay prompts, rubric criteria). A document database stores the entire test and question set as an embedded document tree, retrieving an entire 50-item exam in a single index-backed read operation rather than traversing multi-table relational joins.
